# Corporate UI Guidelines

> Рабочий справочник по визуальной системе, адаптиву и UX для корпоративных интерфейсов.
>
> Этот файл фиксирует правила, подтвержденные текущими референсами проекта. Если конкретное значение здесь не указано, его нельзя додумывать: следует использовать существующий токен/компонент или запросить уточнение.

---

## 1. Источники и приоритет правил

При проектировании использовать следующий приоритет:

1. **Этот справочник и подтвержденные токены проекта** — визуальная система и технические правила.
2. **Существующие компоненты продукта** — если они уже реализуют подтвержденное правило.
3. **UX-паттерны из _Designing Interfaces: Patterns for Effective Interaction Design, 3rd Edition_ (Jenifer Tidwell, Charles Brewer, Aynne Valencia, O’Reilly, 2020)** — руководство по поведению интерфейса и выбору UX-паттернов.
4. Если продуктовая логика или утвержденный макет расходятся с общим UX-паттерном, расхождение нужно обозначить, а не молча заменять продуктовое решение.

Книга используется как UX-руководство, а не как визуальный шаблон. Визуальная реализация всегда должна соответствовать нашей дизайн-системе.

## 2. Базовые UX-принципы

- Проектировать от **цели пользователя**, а не от набора функций.
- Часто используемые действия и важные данные должны быть доступны сразу.
- Сложные задачи разбивать на понятные шаги/секции, не перегружая один экран.
- Интерфейс должен постоянно давать обратную связь о состоянии системы и результате действий.
- Поддерживать **safe exploration**: пользователь должен иметь возможность пробовать, отменять и возвращаться без лишнего риска.
- Поддерживать **spatial memory** и habituation: стабильные элементы не должны без причины менять положение и поведение.
- Для редких/новых задач интерфейс должен помогать и объяснять; для регулярных/экспертных сценариев — не мешать эффективности.
- Не заставлять пользователя принимать решения раньше, чем это действительно необходимо; использовать разумные defaults и progressive disclosure.
- Для Dashboard показывать прежде всего актуальную и actionable-информацию, убирать второстепенное, обеспечивать визуальную иерархию и drill-down в детали.
- Для больших наборов данных использовать понятные списки, таблицы, карточки, фильтры и сортировки; не усложнять визуализацию без необходимости.

## 3. Responsive / Breakpoints

### 3.1. Диапазоны

| Диапазон | Роль | Правило |
|---|---|---|
| `> 1440` | XL | Масштабирование от базового экрана пропорционально `vw` |
| `1200–1440` | Base | Основной диапазон проектирования. Все базовые макеты строятся здесь |
| `960–1199` | Breakpoint | Наследует значения от Base, если нет локального override |
| `640–959` | Mobile | Следующий breakpoint; здесь применяется mobile typography scale |
| `390–639` | Breakpoint | Наследует от `640–959`, если нет локального override |
| `< 390` | XS | Масштабирование пропорционально `vw` от 390 |

### 3.2. Наследование

Главное правило:

> При уменьшении экрана значения наследуются с предыдущего большего breakpoint. Новое значение задается только как явный override.

То есть не нужно дублировать одинаковые правила на каждом breakpoint.

### 3.3. Что масштабируется

При масштабировании выше 1440 и ниже 390 могут пропорционально масштабироваться:

- типографика;
- размеры контентных областей;
- ширины колонок;
- размеры крупных layout-блоков, когда это предусмотрено компоновкой.

### 3.4. Что не масштабируется

Фиксированными остаются:

- линии и strokes;
- border width;
- тени и их offsets/blur/spread;
- базовые spacing-токены `8 / 12 / 24 / 48`;
- grid gutter `24px`;
- крайние grid offsets `12px`.

Пример: линия `1px` остается `1px` на любом экране.

## 4. Grid / Layout

Сетка — это **система пропорций и ритма**, а не требование верстать каждый экран literal CSS Grid на 12 колонок.

Если используется `flex`, карточки, таблицы или иной layout, сетка помогает определить:

- ширины блоков;
- расстояния между блоками;
- общий визуальный ритм;
- кратность размеров.

### 4.1. Базовая сетка 1440 без навигации

| Элемент | Значение на 1440 | Поведение |
|---|---:|---|
| Крайний отступ слева | `12px` | фиксированный |
| Крайний отступ справа | `12px` | фиксированный |
| Рабочая колонка | `94px` | сжимается/растягивается |
| Gap между колонками | `24px` | фиксированный |
| Шаг направляющей | `118px` | производный: `94 + 24` |

`118px` — не отдельная ширина контентной колонки, а шаг центральных направляющих, разделяющих фиксированный gap `24px`.

### 4.2. Сетка с левой навигацией — открыта

Левая навигационная панель: `264px`.

| Элемент | Значение на 1440 |
|---|---:|
| Крайние offsets | `12px` |
| Рабочая колонка | `72px` |
| Gap | `24px` |
| Шаг направляющей | `96px` (`72 + 24`) |

### 4.3. Сетка с левой навигацией — закрыта

Левая навигационная панель: `60px`.

| Элемент | Значение на 1440 |
|---|---:|
| Крайние offsets | `12px` |
| Рабочая колонка | `89px` |
| Gap | `24px` |
| Шаг направляющей | `113px` (`89 + 24`) |

В Figma-референсе для этого варианта также присутствует вспомогательный guide `16 columns (89px)`. Его использовать как визуальную направляющую, а не как обязательное требование к DOM/CSS структуре.

### 4.4. Практическое применение

Если, например, в `flex` нужно разместить 4 карточки:

- сохранить `24px` между соседними карточками;
- заполнить доступную ширину без произвольных зазоров;
- учитывать состояние навигации;
- стараться использовать размеры блоков, кратные `12px`, если это не ухудшает задачу;
- для крупных смысловых групп использовать расстояние `48px`.

## 5. Spacing

Базовая шкала:

`8 → 12 → 24 → 48`

| Токен | Рекомендуемое применение |
|---:|---|
| `8px` | Очень компактные внутренние отступы, расстояния между мелкими элементами |
| `12px` | Вложенные/небольшие карточки, компактные блоки |
| `24px` | Основные карточки, стандартный внутренний padding, стандартный gap |
| `48px` | Разделение крупных смысловых групп/секций |

Правила карточек:

- внутренний базовый padding карточки: `12px` или `24px` в зависимости от размера и вложенности;
- расстояние между карточками/блоками: `24px` или `48px`;
- по возможности сохранять кратность `12px` для крупных размеров и пропорций;
- spacing-токены фиксированные и не масштабируются через `vw`.

## 7. Color system

### 7.1. Общее правило

- Светлый интерфейс использует **Light theme tokens**.
- Темный интерфейс использует **Dark theme tokens**.
- В компонентах использовать **семантические токены**, а не произвольные HEX.
- Альфа-канал является частью токена и не должен заменяться визуально похожим непрозрачным цветом.

Все семантические варианты общего `badge`, включая базовый и `neutral`, используют `--system-elements-semantic-{tone}-secondary-fade` для заливки и Primary соответствующего тона для текста. Обычный fade не является фоном бейджа. Вариант `badge.default` сохраняет отдельно согласованные `--background-surface-4`, рамку `--design-elements-border-default` и текст `--text-tertiary`.

## 12. Cards and component composition

По последнему решению пользователя от 09.10.2026 общие карточки используют `--shadow-raised` (5%) в обычном состоянии и при наведении. Общий `--card-shadow` задаётся на каждой карточке и не меняется при hover; усиление до `--shadow-primary` и переход тени удалены. `backdrop-filter` карточек, KPI-плашек и бейджей отключён в обеих темах; цвета, прозрачность и семантические фоны сохраняются. Тени бейджей, кнопок, дроверов и сайдбара не меняются. Временная маска границы контента удалена; явно бесфоновые вложенные блоки сохраняют отсутствие тени.

Линейные графики используют общую анимацию длины SVG-пути (`stroke-dashoffset`, 650ms); точки проявляются после построения линии (195ms = 30% общего токена длительности). Идентичный redraw не пересоздаёт SVG, а redraw размеров переносит активные эффекты на новую геометрию через `KeyframeEffect.target` и `setKeyframes`, не перезапуская время. После завершения исходные stroke, толщина, цвета и тени сохраняются. Анимация подтверждена пользователем 09.10.2026. Внешняя тень сайдбара не обрезается; экспериментальный `clip-path` навигации удалён как неэффективный.

- Базовая анимация графиков общая: `BNTUI.bindChartMotion()`, `--chart-motion-duration` (650ms), `--chart-motion-easing`. Столбики раскрываются от основания, горизонтальные — от начала; отрицательные значения раскрываются в обратную сторону. Донаты последовательно заполняются по часовой стрелке через исходную геометрию секторов, без подложки, mask, изменения opacity, цвета или масштаба. Линии раскрываются слева направо. Подписи, оси, сетка и легенда неподвижны; размеры и толщина линий не анимируются. Включены самостоятельные графики `financial-chart__viewport`, в том числе «План vs Факт», а не только `chart-card`.
- Запуск при первом появлении графика и изменении данных; hover/highlight и resize не перезапускают ту же диаграмму. Скрытые диаграммы ждут видимости. `prefers-reduced-motion: reduce` и печать показывают финальное состояние сразу. `data-chart-motion="off"` явно отключает анимацию в области. Отмена и удаление восстанавливают исходные пути доната, listener/observer очищаются через `chartMotion.destroy()`.
- Общая кнопка отмены дровера рендерится через `BNTUI.renderDrawerCancel()`: `button-smallest-secondary-radius typography-button-smallest`, перед «Отмена» — существующий `Cross` из общего спрайта. Действующая отчётная логика и проекты используют этот мастер, не старые кнопки студии.

- Заголовок общего компонента `card-with-image` во всех вариантах использует `typography-caption-smallest` и соответствующие токены; правило действует и для оборудования, и для шаблонов.
- Общие минимальные размеры `card-with-image`: высота `--card-with-image-min-height` (340px), ширина `--card-with-image-min-width` (320px). Гриды `templates-grid`, `asset-cards` и `schedule-list` используют gap `--space-3` и `repeat(auto-fill, minmax(var(--card-with-image-min-width), 1fr))`, без ограничения числа колонок. Все строки выравниваются по высоте самой большой карточки через `grid-auto-rows: 1fr`. Общая оболочка `#page-content` использует всю доступную ширину и штатный `--shell-gutter`, без старого ограничения 1760px.
- Надзаголовок ограничен двумя строками, заголовок и описание тремя строками с многоточием. `BNTUI.bindImageCards()` измеряет максимальную естественную высоту `card-with-image__body` в группе и обновляет её при изменении текста, ширины, видимости и загрузке шрифтов. Текстовые блоки карточек начинаются на одном уровне; кнопки `card-with-image__actions` или область `card-with-image__progress` закреплены внизу, свободное место располагается над ними. Верхний радиус `__body` — `--space-3`.
- `data-block` задаёт единственную внешнюю поверхность и padding `--space-3`. Вложенный непосредственный `card-body` не добавляет ещё одну рамку, фон, тень, blur или padding; рамки самостоятельных инструментов и показателей сохраняются. Рассылки используют `data-block scenario-panel` с заголовком Caption Smallest, описанием Body Smallest и gap `--space-1` между ними. Почты рендерятся табличными пилами с крестиками через `BNTUI.renderFilterSummary(..., {rows: 3})`: три ряда зарезервированы сразу, gap `--space-1`, остаток раскрывается в общем rollover-счётчике. Переполнение измеряется по фактической геометрии и обновляется при resize, изменении содержимого и загрузке шрифтов. Крестик удаляет только адрес; последнего получателя нельзя убрать.
- `logistics-action-list` является общим компонентом. Кнопки сохраняют hug по содержимому и штатный padding; соседние кнопки растягиваются до высоты большей в ряду через `align-items: stretch`, без фиксированного потолка высоты. Нечётная последняя кнопка занимает весь ряд. В рассылках иконка только у третьего действия «Редактировать рассылку», которое использует primary smallest. Оно открывает заполненный общий дровер: сохранение обновляет текущую рассылку, не создаёт новую и сохраняет состояние паузы. Удаление всей рассылки доступно только явной кнопкой «Удалить рассылку» вместо «Отмена»; закрытие крестиком дровера или Escape ничего не удаляет и не сохраняет.
- `metrics-grid` имеет шесть равных колонок по умолчанию и gap `--space-2`, переиспользуя оформление ячеек `dt3-metrics scenario-impact`. Вариант `metrics-grid--paired` с `data-metrics-for="ID"` связывается с адаптивным гридом карточек: `BNTUI.bindMetricsGrids()` измеряет его ширину, минимальную ширину карточки и gap, задавая вдвое больше колонок через `--metrics-grid-columns`. Пропорции 3/6, 4/8 и далее пересчитываются при resize, изменении ширины сайдбара и вставке содержимого. Только у этого варианта gap по обеим осям равен `--space-3`, как у `div-block` и `schedule-list`; границы пары верхних ячеек совпадают с границами одной нижней карточки. Другие KPI-гриды сохраняют `--space-2`.
- Заполненная страница рассылок оборачивает `metrics-grid--paired` и `schedule-list` в общий `content-block`: расстояние между этими рядами `--space-4` (16px). Внутренний gap сеток задаётся их компонентами. Пустое состояние сохраняет самостоятельную центрированную раскладку.
- `dt3-risk-toggle` является общим компонентом, перенесённым из цифрового двойника без изменения его геометрии и токенов. `BNTUI.renderToggle()` рендерит кнопку с `aria-pressed`, track, knob и label; состояние данных обновляет адаптер страницы. Вариант `tone: "positive"` / `dt3-risk-toggle--positive` задаёт включённому track `--system-elements-semantic-positive-primary`; базовый тогл сохраняет брендовый цвет. В рассылке он стоит слева, статус справа в одной строке `page-title-actions`: включённая — «Деактивировать» и `badge green`, выключенная — «Активировать» и `badge orange` (Warning). После переключения сохраняется фокус и обновляются статус и число активных рассылок.
- Общий `button-smallest-secondary-radius--error` сохраняет геометрию secondary-кнопки, используя текст и иконку `--system-elements-semantic-error-primary` и фон `--system-elements-semantic-error-secondary-fade` в обеих темах. Он применяется к действию «Удалить рассылку».
- Общий вариант `badge default` использует фон `--background-surface-4`, текст `--text-tertiary` и рамку `--design-elements-border-default`, сохраняя размеры, hug и оптическую центровку мастер-компонента. Рамка учитывается во внутреннем вертикальном padding, не увеличивая однострочные высоты 20/24/28px. Источник и год в `template-meta` рендерятся через `BNTUI.badge(value, 'default')`; количество блоков остаётся `badge neutral`.
- Уведомления рендерятся только общим `BNTUI.toast(title, message, {tone})`: варианты `default`, `positive`, `warning`, `error`, `neutral`. Заголовок — Caption Smallest, описание — Body Smallest, оба `--text-primary`. Ширина 320px ограничена экраном, высота hug, padding `--space-3`, gap `--space-2`, радиус `--space-2`, blur `--backdrop-blur-raised`. Только Default сохраняет рамку `--design-elements-border-default`; Positive, Warning, Error и Neutral — без рамки. Первая рамка иконки — общий `layout-item-icon` (32px), закрытие — `sign_BTN_small` (24px). Positive использует check, Warning/Error — warning, Neutral/Default — info. Если отдельный заголовок не задан (одиночный текст, пустое описание или пустой title), заголовок — «Внимание!», имеющийся текст рендерится описанием Body Smallest. Явно заданные title и message сохраняются; семантический тон, стек и ручное закрытие не меняются. ARIA-подпись крестика сохраняет исходный текст, чтобы уведомления с общим заголовком оставались различимы.

Фон первой иконки default — `--background-brand-fade-3` (#C9DEE8, 20%), цвет — `--design-elements-icon-primary`. Остальные варианты берут фон и цвет из своих семантических токенов. Все поверхности и тексты переключаются с темой; рамка Default имеет прозрачность из токена (8% Light, 10% Dark). Уведомления выстраиваются в общем `toast-root` по порядку появления и остаются до ручного закрытия, без таймера и замены предыдущего. Длинный стек использует `ui-scrollbar`. Закрытие удаляет только выбранный тост, возвращая клавиатурный фокус на соседний крестик или исходный элемент.

### 12.3. Shared controls, range и поля

Закрепленные правила для общих контролов применять одинаково на всех страницах, где используется этот паттерн.

- В `page-title-actions` группа `page-title-actions__buttons` выравнивается по нижнему краю строки через `align-self: flex-end`, в том числе при многострочном заголовке. Это не меняет выравнивание отдельной подписи источника.
- Контурные SVG-иконки сохраняют толщину `1.5px` при любом размере: использовать `stroke-width="1.5"` и `vector-effect="non-scaling-stroke"` на геометрии. В кнопках Smallest размер иконки остаётся `20px`. Контур, преобразованный в залитый `path`, не сохраняет толщину при масштабировании; для таких контурных иконок восстанавливать исходную осевую линию и настоящий stroke.
- В кнопках Small SVG занимает рамку 24×24. Символ `Pencil` сохраняет исходный `viewBox="0 0 24 24"` и внутренние поля рисунка; обрезать рамку по границам геометрии и растягивать её обратно до 24px нельзя. Цвет контура наследуется через `currentColor`.
- `ui-dropdown` и `ui-zoom` считаются общими контролами; локальные страницы могут задавать размеры через CSS-переменные, но не должны менять базовую механику и токены без отдельного согласования.
- `speed-dial-secondary` используется только для вторичных контекстных действий; primary actions должны оставаться видимыми кнопками/ссылками, а trigger обязан поддерживать `aria-haspopup="menu"` и `aria-expanded`.
- Размер `speed-dial-secondary` задается через `BNTUI.speedDialSecondary({size})`: по умолчанию `smallest` сохраняет квадратный trigger с подписью снизу и пункты `Body Smallest`; `small` использует `button-small` с горизонтальной подписью `Button Small`, навигационный шеврон, пункты `Body Small`, иконки `24px` и состояния `Caption Small`. ## 13. Navigation states

На desktop учитывать три состояния layout:

1. **Без навигации** — базовая сетка 1440.
2. **Левая навигация открыта** — панель `264px`.
3. **Левая навигация закрыта** — панель `60px`.

Справа может появляться дополнительная контекстная навигация. Ее размеры, состояния и поведение пока не зафиксированы; до появления подтвержденного компонента их нельзя додумывать или переносить с левой панели.

Переключение состояния навигации не должно ломать визуальный ритм, spacing и приоритет контента.

## 14. Implementation rules

### 14.1. Tokens first

Не использовать случайные значения в компонентах, если они уже описаны токенами:

- typography;
- color;
- spacing;
- border;
- shadow;
- responsive rules.

### 14.2. Inheritance first

На меньшем breakpoint сначала наследовать значение предыдущего большего breakpoint. Добавлять override только при реальной необходимости.

### 14.3. Fixed vs scalable

Перед использованием `vw`, `clamp()` или другой fluid-формулы определить, относится ли величина к:

- **scalable content/layout** — может масштабироваться;
- **fixed rhythm/detail** — остается фиксированной.

Не масштабировать strokes, borders, shadows и spacing-токены.

### 14.4. Accessibility and interaction

- Все интерактивные элементы должны иметь понятный focus state.
- Не полагаться только на hover для критичных действий.
- Состояния success/error/warning/neutral должны выражаться семантическими токенами и, где необходимо, текстом/иконкой, а не только цветом.
- Поддерживать предсказуемую keyboard navigation там, где интерфейс предполагает интенсивную работу с данными.

### 14.5. Общие поля формы

- Значения всех общих полей (`form-input`, одиночный/множественный выбор, дата и время) до взаимодействия используют `--text-tertiary`, даже если значение задано по умолчанию. После выбора, ввода или входа и выхода из поля сохраняется `--text-primary` через `is-touched`, в том числе после очистки. `has-selection` и `has-value` описывают наличие значения, а не его цвет. Программная синхронизация не помечает поле как измененное. Placeholder обычного `form-input__control--text` наследует цвет поля и имеет `opacity: 1`, без браузерного серого оттенка.
- Однострочные `form-input__control` и внешняя поверхность даты/времени `equipment-date-input` имеют общую высоту `--form-input-control-height: 40px` с `box-sizing: border-box`. Иконка и значение располагаются по центру, у выбора и даты только горизонтальный padding; вертикальные отступы не увеличивают высоту поверх 40px. Значения используют одни токены Body Smallest, включая диапазон ниже 1440px. Многострочный textarea сохраняет `height: auto` и собственную минимальную высоту.
- Одиночный выбор без поиска использует эталон «Приоритет» из закупок: `BNTUI.renderFormInput({name, label, options, value, mode: "single"})`. Опции задаются строками или объектами `{value, label}`. Это вариант общего `form-input`, а не отдельный dropdown.
- Контракт одиночного выбора: `data-form-input-mode="single"`, `data-form-input-option`, `data-form-input-selected`. Общий JS управляет открытием, выбором, клавиатурой и ARIA; страница только читает значение из события `change` и синхронизирует данные через `BNTUI.syncSingleFormInput(root, value)`.
- Пилы применённых фильтров рендерятся через общий `BNTUI.renderFilterSummary(groups, options)` из эталонных фильтров оборудования и закупок. Группы задаются как `{key, label, count?, values: [{value, label}]}`; `counted: true` всегда показывает счётчики, `readonly: true` полностью сохраняет вид списка с крестиками, но отключает их и не выдаёт атрибуты удаления. Общий контракт `data-filter-summary-group/toggle/menu` управляет ARIA, закрытием по повторному нажатию, снаружи и Escape, возвратом фокуса и размещением rollover в пределах экрана. Удаление значений остаётся в адаптере данных страницы. Прокрутка использует `ui-scrollbar`.
- Общий `pill`, его счётчики и `badge` при ширине окна до 1440px включительно имеют однострочную высоту `var(--space-5)` (24px) вне таблиц и `calc(var(--space-5) - var(--space-1))` (20px) внутри таблиц. Свыше 1440px однострочная высота обоих компонентов везде равна `calc(var(--space-5) + var(--space-1))` (28px). Это минимальные высоты: вне таблиц при переносе на две и более строки используется hug (`height: auto`), без обрезания текста. Табличный бейдж всегда однострочный: ширина по содержимому до `--table-badge-max-width` (280px), длинная подпись обрезается троеточием в `badge__label`; короткая не растягивается. Пилы сохраняют свой существующий hug/overflow-контракт. Единое правило живёт в `components.css` через `--pill-badge-height` и одинаково работает в обеих темах, в том числе для бейджей дровера. `box-sizing: border-box` включает padding в высоту; у бейджа вертикальный padding ограничивается свободным местом одной строки, чтобы дробный line-height не увеличивал табличные 20px. Текст и иконки центрируются по высоте через `align-items: center`, а строки grid через `align-content: center`, без baseline-псевдоэлементов. Ширина пилов и счётчиков — по содержимому (`fit-content`) в пределах доступного места; строки rollover занимают ширину списка. Обычные пилы, счётчики и бейджи разрешают перенос; выбранные значения внутри `form-input` сохраняют собственную механику измерения, primary-тега и rollover. Инфокнопка `scenario-copy` центрируется относительно первой строки Caption Small через её токен line-height, а не относительно фиксированной высоты `20px` заголовка.
- Оптическое выравнивание текста пилов и бейджей выполняет общий `BNTUI.bindCompactLabels()`: по `Canvas TextMetrics` измеряются фактические верхняя и нижняя границы букв, а `--compact-label-offset` центрирует их внутри элемента без изменения типографики, line-height, ширины и hug-высоты. Для переноса учитываются верх первой и низ последней строки. Подписи измеряются при вставке, раскрытии, смене текста, resize и загрузке шрифта; существующие иконки и действия остаются без изменений. Старый текст без обёртки автоматически получает общий `badge__label` или `pill__title`. Padding пилов ограничен свободным местом вокруг 20px иконки, чтобы однострочный пил в таблице до 1440px оставался ровно 20px. При отсутствии метрик остаётся обычная центровка CSS.
- В предпросмотре конструктора после Ghost-кнопки располагается `page-title-actions` с общим `scenario-copy`: название Caption Small, инфокнопка сохранения, бейдж доступа и пилы «Формы»/«Графики» со списками добавленных блоков. Готовые блоки считаются формами; счётчик графиков включает все фактически построенные графики, в том числе внутри готовых форм и отдельные графики по показателю. Пустой график с empty state не входит в счётчик; скрытие таблиц не меняет список графиков. Общий `BNTUI.renderFilterSummary()` не рендерит группы с нулевым счётчиком. Все таблицы содержимого отчёта и предпросмотра, включая сравнительные, матрицы, план/факт, баланс и CAPEX, используют `table-block > table-wrap > data-table` с общими текстовыми, числовыми, процентными и progress-ячейками, сохраняя данные корректировок. Доступ «Личный» использует `badge neutral`, «Общий» — `badge purple`, «ПЭО» — `badge mustard`; цвета берутся из семантических токенов обеих тем. Обе кнопки «Сохранить шаблон» открывают один общий дровер с названием, описанием, одиночным выбором формы доступа и footer «Сохранить»/«Отмена». Сохранение не переключает страницу и сохраняет блоки, параметры и корректировки шаблона.
- Контекстный выбор из `dt3-zone-dropdown ui-dropdown` рендерится через `BNTUI.renderDropdown({id, label, options, value, size})`, опции — `{value, label, count?}`. `size: "small"` задаёт высоту small; кнопка hug по содержимому, только выпадающее меню ограничено `300px` и привязано к правому краю кнопки. Варианты — body-small с переносом строк, выбранный вариант и trigger — caption-small; количество в скобках использует `--text-tertiary`. Контракт `data-ui-dropdown`, `data-ui-dropdown-option`, `data-ui-dropdown-label` общий для цифрового двойника и «Данных»; страница получает `change` на корне и читает `dataset.value`.
- Неизменяемое значение использует тот же `form-input__control--text` с `readonly disabled tabindex="-1"`: текст сразу `--text-primary`, без hover/focus-реакции и `is-touched`. Многострочное обоснование использует `form-input__text-field`, `form-input__text-icon` с символом `Pencil` и общий textarea, как в заявке на закупку.
- Календарь `equipment-date-*` использует `BNTUI.renderDateField`, `syncDateField`, `handleDateFieldClick` и `closeDatePickers`; `prefix` позволяет подключить прежние атрибуты страницы без копии механики. У общего `bnt`-контракта обработчики подключены в `ui.js`. Пара дат располагается в `equipment-date-grid`, ограничения задаются `min`/`max` в ISO-формате.
- Формы «Данные», корректировки «Отчётов» и «Рассылки» используют одну разметку `BNTUI.renderDrawer({id, title, fields, footer, formAttributes})` и общую механику открытия/закрытия студии: возврат фокуса, Tab внутри дровера, Escape сначала закрывает открытый dropdown или календарь. Необязательный `description` помещается в общую инфокнопку рядом с заголовком через `scenario-copy__title-row`; `data-drawer-info` открывает общий инфопоповер, без заметки в теле формы. Заголовок корректировки отчёта: «Корректировка для [название из таблицы]», без повторного заголовка внутри. Корректировка сохраняется только для текущего шаблона. Старые обёртки модалки, дополнительную линию под header и служебные заметки не переносить.
- Шапка «Конструктора» повторяет `page-title-actions` из «Отчётов»: описание в общем инфопоповере, «График по показателю» и «Предпросмотр» в `speed-dial-secondary` размера small, «Сохранить шаблон» отдельной primary small. Отдельного фильтра нет: параметры данных нужны для предпросмотра и используют тот же дровер, одиночные поля и пару дат, что «Отчёты». В предпросмотре заголовок «Настройка данных для предпросмотра», footer «Применить»/«Отмена»; параметры применяются только при подтверждении. «Применить» закрывает дровер и показывает текущие блоки через общий рендер отчёта внутри страницы «Конструктора», ниже кнопки Ghost Smallest «Конструктор» с `StrokeReturn`. В хлебных крошках «Управление / Конструктор / Предпросмотр»; общий `BNTShell.setBreadcrumbs()` сохраняет разметку и ссылки оболочки. Кнопка и пункт «Конструктор» возвращают прежнюю форму и холст без изменения блоков или перехода в «Отчёты». Состояние предпросмотра временное; после перезагрузки открывается конструктор с сохранёнными параметрами.
- В галерее «Шаблоны» primary small «Создать шаблон» с общим плюсом открывает `/builder.html` с новым пустым черновиком, сохраняя пользовательские шаблоны и корректировки. «Открыть» показывает выбранный шаблон на той же странице, а не переводит в «Отчёты»; над общей `scenario-copy` шапкой предпросмотра находится Ghost Smallest «Шаблоны» с `StrokeReturn`. Шапка, бейдж доступа и readonly-пилы форм/графиков переиспользуются из предпросмотра конструктора. Крошки — «Управление / Шаблоны / Предпросмотр»; возврат восстанавливает галерею и фокус исходной кнопки.
- В просмотре шаблона «Редактировать» доступно для «Личный»; «Общий» и «ПЭО» открываются без редактирования. Кнопка включает существующие корректировки значений и редактирование макета. «Закрыть редактирование» открывает общий дровер «Сохранить шаблон» с текущим названием, описанием и формой доступа. «Сохранить» обновляет тот же ID, не создавая копию; «Отмена» оставляет режим редактирования открытым. Локальная версия встроенного шаблона заменяет его по ID во всех общих списках, без дубликатов. Поле `access` хранит форму доступа отдельно от категории `tag`; прежние шаблоны с доступом в `tag` поддерживаются.
- Общая шапка дровера `filter-modal__head` выравнивает однострочный заголовок и кнопку закрытия по базовой линии. При двух и более строках оба элемента выравниваются по верхнему краю через `is-title-long` и `align-items: flex-start`. Общий `BNTUI.bindDrawerHeaders()` после расчёта текущей раскладки считает реальные строки текста через `Range.getClientRects()`, а не высоту всей коробки заголовка. Состояние обновляется при открытии, смене текста, ширины и загрузке шрифта. Правило одинаково для форм, фильтров и пустых дроверов; локальную механику страницы не добавлять.
- У icon-only кнопки закрытия шапки базовая линия формируется невидимым текстовым `::before` с теми же метриками Caption Small, что у заголовка. SVG расположен абсолютно по центру кнопки и не участвует в расчёте baseline: иначе браузер выравнивает текст относительно нижнего края иконки, сдвигая заголовок вниз. Размер кнопки, иконки и выравнивание многострочной шапки не меняются.
- Общий пустой компонент рендерится через `BNTUI.renderEmptyState(message, {size, title, action})`. По умолчанию заголовка и кнопки нет. Необязательный `title` использует `empty-state__title` / Label Base; `action: {label, attributes}` — обычную secondary Small, как в эталоне рассылок. Базовый small сохраняет иллюстрацию `EmptyStateBox` 120×120 и body-small; компактный smallest (`empty-state--smallest`) использует 96×96 и body-smallest. Размер иллюстрации берётся из токенов. Общий `empty-state__content` ограничивает ширину до 320px. Страница с единственным Empty использует `page-content--empty`: пустое состояние заполняет доступную высоту, без фиксированного размера.
- Пустые таблицы используют `BNTUI.renderEmptyTableRow(columnCount, message)`: строка `data-table-empty`, единая `data-table__empty-cell` с `colspan` по числу колонок и тот же Empty Smallest, без отдельной иллюстрации, заголовка или кнопки. Общий `BNTUI.updateTableEmptyState()` вызывается в binding таблиц до измерения колонок и высоты, добавляет заглушку в пустой `tbody`, учитывает скрытые фильтром строки и убирает только собственную заглушку при появлении данных. Скрытые строки не удаляются; пустая ячейка не наследует ограничение первой колонки дерева. Старые текстовые заглушки заменяются этим же рендером с сохранением исходного сообщения.
- Пустой вариант дровера задаётся через `BNTUI.renderDrawer({id, title, emptyMessage})`: шапка с крестиком сохраняется, нижний divider и footer отсутствуют. В `filter-modal__body--empty` по центру располагается тот же Empty Smallest с `emptyMessage` под иллюстрацией; при нехватке высоты работает общий scrollbar. В отчёте таблица без числовых значений (пустые ячейки или прочерки) не выводится. Ноль считается значением. Пустой блок участвует в раскладке как блок без таблицы: соседние блоки без таблиц образуют пару, непарный блок занимает всю ширину.
- Выбор времени рендерится через `BNTUI.renderTimeField({name, label, id, value})`, значение хранится в формате `HH:mm`, диапазон `00:00–23:59`. Поле и поповер наследуют общий календарный компонент `equipment-date-*`, часы и минуты используют общие числовые `form-input` со степпером.
- Время применяется кнопкой «Применить» или Enter в числовом поле. «Отмена», Escape и закрытие поповера не сохраняют черновик. Иконка часов берется из `BNTUI.icon("clock")`, цвет наследует `--design-elements-icon-primary`.
- Дровер формы без поиска использует `filter-modal__body--form`, поля находятся в `filter-modal__fields ui-scrollbar`. Локальные поля и собственные механики выбора рядом с общими компонентами не создавать.
- `BNTUI.bindDrawer(host)` возвращает идемпотентный контроллер `open(options, trigger, cleanup)` / `close({restoreFocus})`. Он использует `renderDrawer`, ARIA триггера, стандартные close/overlay, Tab внутри формы и возврат фокуса; обработанный вложенным компонентом Escape не закрывает форму. Cleanup снимает обработчики полей перед удалением содержимого.
- `BNTUI.bindMultiFormInput(root, {values, required})` подключает весь контракт общего `renderFormInput` для множественного выбора: поиск и его очистку, «Всё» с tri-state как у «Локации», выбранные пилы, их удаление, rollover счётчика, позиционирование, клавиатуру и пересчёт overflow. Возвращаемый cleanup снимает обработчики. При пустом необязательном поле предупреждения нет. `toggleMultiSelectValue` / `removeMultiSelectValue` сохраняют прежнее поведение фильтров по умолчанию; `allowEmpty` / `toggleAll` включают контракт выбора исполнителей.
- «Проекты» использует общий Empty с заголовком, текстом и «Создать проект», без отдельной шапки «Проекты». Дровер «Новый проект» содержит название, статус, описание, бюджет, множественный выбор исполнителей и пару общих календарей. Список исполнителей: Караев Р.Р., Ибраев С.С., Смагулов Е.Т., Ахметов Е.Е., Байкенова М.М., Байкенов А.А., Ахметов У.М.; первые три выбраны при открытии. Пока это форма-заглушка: «Создать» только закрывает дровер и возвращает фокус, без записи проекта, сохранения в storage или уведомления об успехе.
- «Создать график по показателю» в конструкторе и отчётах использует тот же дровер создания графика, что раздел «Данные»: общие поля набора данных, показателя, типа и ширины, footer «Добавить график»/«Отмена», пояснение в инфокнопке заголовка. Смена набора сохраняет тип и ширину. Подтверждение добавляет график в текущий шаблон и оставляет пользователя на исходной странице; только создание из «Данных» сохраняет прежний переход в «Отчёты». Отмена не меняет данные шаблона.

### 14.6. Общая рабочая область

- Каркас цифрового двойника и конструктора использует общий `layout-workspace`: `layout-toolbar`, `layout-body`, `layout-surface`, правый `layout-drawer` и прокручиваемый `layout-drawer-body`. Внешняя область конструктора дополнительно называется `canvas`. Правила каркаса и списка живут в `components.css`; 3D-сцена и её управление остаются в своей странице.
- Общий `BNTUI.bindWorkspaces()` обслуживает `data-workspace-toggle/open/close`, ARIA, возврат фокуса, вкладки `role="tab"` с `data-workspace-tab` и панели `data-workspace-panel`. `workspacechange` передаёт `{open, tab}` адаптеру страницы. Стрелки, Home и End работают только внутри вкладок. Закрытие по Escape включается явно через `data-workspace-dismiss`, чтобы не менять навигацию цифрового двойника.
- `data-workspace-fill` включает измерение доступной высоты после раскладки и её обновление при изменении размеров и загрузке шрифта. Прокручивается тело drawer, а его вкладки остаются на месте. Строки вариантов рендерятся одним `BNTUI.renderWorkspaceItem({label, caption, icon, actionIcon, attributes})`, без вложенной кнопки действия.
- У конструктора внешний контейнер использует `content-block`, в том числе в предпросмотре. Холст расположен слева, «Блоки и формы» справа, в том числе на узком экране. Каталог открыт по умолчанию; выбор вкладки и сворачивание сохраняются при обновлении холста. Поверхность холста использует `layout-surface--secondary` и `--background-secondary`. Описание холста, блоков и форм находится в общих инфокнопках. Вкладки называются «Блоки» и «Формы», подпись с инфокнопкой центрируются вместе, расстояние между ними `--space-1`; инфокнопка не вкладывается в кнопку таба. Инфотекст форм: «Здесь вы найдёте комплексные блоки и составные таблицы». Однострочный общий таб использует базовый минимум 36px, многострочная подпись увеличивает высоту по содержимому; отдельный компактный компонент не создаётся.
- `layout-toolbar` растёт по содержимому с вертикальным padding `--space-3` (12px); группы добавляют только горизонтальный отступ, не дублируя вертикальный. Кнопка высотой 36px даёт шапку 60px. Открытый общий Speed Dial имеет `z-index: 90` на корневом элементе, выше шапки рабочей области. У scoped search поле прозрачно, системные тень, outline и крестик поиска убраны; очистка остаётся за общей кнопкой компонента.
- `canvas-block` использует общую поверхность KPI: фон `--background-surface-4`, обводку `--design-elements-border-default`, тень `--shadow-raised`, радиус `--space-2`, padding `--space-3`. Подписи оформляются через `layout-item-label`; drag и удаление используют настоящие icon-only кнопки Smallest Secondary (36px) с `financial-interface.svg#Drag` и `#Cross`. Drag содержит шесть залитых точек. Однострочные основная и дополнительная подписи центрируются с кнопками; при переносе кнопки сохраняют положение относительно двух однострочных подписей, а не середины выросшей карточки.
- `BNTUI.updateCanvasGrid()` измеряет доступную ширину `canvas-grid`, учитывая его padding и gap, и задаёт число равных колонок так, чтобы ширина блока не превышала 600px. Допустимы 1, 2, 3, 4 и больше колонок. Общий binding рабочей области наблюдает также сам грид, поэтому число колонок пересчитывается при открытии/закрытии drawer и изменении экрана, без изменения порядка блоков и модели данных.
- Шапка конструктора содержит заголовок холста и кнопку «Блоки и формы», которая раскрывает каталог. Отдельная кнопка «Добавить блок» и её постоянная вертикальная черта убраны. Под шапкой раскрытого drawer в конструкторе и цифровом двойнике расположен общий горизонтальный `ui-divider brand-divider`: продолжение нижней границы toolbar с внутренними отступами `--space-3`. При однострочных контролах высотой 36px линия находится на y60; при переносе следует за выросшей шапкой. У внешнего `canvas layout-workspace` все углы имеют одинаковый радиус `--space-2`. Блоки используют залитую иконку управления `nav-management-solid`, готовые формы сохраняют `nav-builder-solid`.
- Native drag блока заполняет `dataTransfer` идентификатором и задаёт `effectAllowed/dropEffect: move`; drag image показывает всю карточку, включая перетаскивание за вложенную кнопку. Drop переставляет блок в существующем массиве шаблона; завершение и отмена сбрасывают источник перетаскивания. Та же механика обслуживает холст и редактирование макета отчёта.
- Drawer конструктора содержит весь каталог добавления, без отдельного сокращённого списка. Самостоятельные показатели относятся к библиотеке, составные сравнительные и матричные представления помечены `catalogGroup: 'forms'`. Текущий каталог включает 21 блок и 11 готовых форм; третьей категории нет. Состав и разметка холста от выбора вкладки и поиска не меняются.
- «Добавить блок» в отчётах открывает тот же каталог в общем полноэкранном правом `filter-modal`, поверх страницы, а не внутри `layout-workspace`. Каталог использует общую разметку вкладок, поиска и списка; прокручивается только `layout-drawer-body`. `BNTUI.renderDrawer({content, form: false})` поддерживает содержимое с собственной поисковой формой без вложенных `<form>`. Плюс в этом дровере пока является заглушкой: только закрывает дровер и возвращает фокус, не меняет шаблон, не обновляет отчёт и не создаёт уведомление. В конструкторе добавление остаётся рабочим.
- Поиск с областями рендерится общим `BNTUI.renderScopedSearch({id, label, placeholder, options, scope, query, active, appliedQuery})`: `dt3-multisearch-field shell-search-field` и search-вариант общего `renderDropdown`. Области используют весь `data-ui-dropdown` контракт, включая ARIA, клавиатуру, закрытие по Escape/снаружи и событие `change`; локальную механику раскрытия не добавлять. Общий `bindScopedSearches()` обслуживает Enter/submit, очистку и смену области; `scopedsearchchange` передаёт `{active, query, scope}` адаптеру данных страницы. В drawer поиск занимает всю ширину и остаётся над вкладками, список прокручивается отдельно.
- Области конструктора — «Все», «Блоки», «Формы». Поиск учитывает название и назначение; отдельная область выбирает соответствующую вкладку, ручное переключение вкладок синхронизирует выбранную область. Ввод без Enter не меняет содержимое. Enter или кнопка поиска скрывает вкладки вместе с их содержимым и показывает найденные варианты: в области «Все» блоки и формы в одном списке. Иконка поиска сменяется крестиком. Нажатие крестика или очистка поля возвращает стандартные вкладки и иконку поиска; выбранная область сохраняется. Отсутствие совпадений отображается общим Empty Smallest. Поиск и область сохраняются при добавлении блока, не записываются в финансовую модель шаблона.

### 14.7. Шкалы и прокрутка

Шкалы общих линейных и столбчатых графиков рассчитываются единым `BNTUI.chartScale()`: положительный целочисленный шаг не меньше 1, равные пропорциональные интервалы, округлённые границы с обязательным делением 0. Автоматически выбираются четыре интервала, явно заданный шаг сохраняется с округлением вверх до целого. Это правило касается только шкалы: данные, значения точек/столбцов и подсказки сохраняют исходную точность, включая малые дробные значения. Компонент `chart-stacked-bars.js` подключается после общего `ui.js`.

При скрытии хлебных крошек общая `app-contextbar` уходит вверх полностью (`translateY(-100%)`, opacity 0); видимая полоса от sidebar gutter под topbar не оставляется. Положение содержимого в потоке не меняется.

### 14.8. KPI отчётов

«Ключевые показатели» в отчётах и предпросмотре конструктора используют общий `analytics-kpi`, включая карточки с `payment-summary-card` и круговым `BNTUI.progressRing()`. Отклонение от плана рассчитывается как `(факт - план) / abs(план) * 100` и округляется до целого процента; исходные финансовые значения сохраняют точность. Знак остаётся в подписи, цвет берётся из общего positive/error-варианта. Кольцо ограничивает дугу диапазоном 0–100%, но подпись сохраняет рассчитанное отклонение, в том числе больше 100%. Без плана или при нулевом плане процент и кольцо не отображаются; без значений используется общий Empty Smallest, а реальные нули остаются значениями. Блок KPI всегда занимает отдельный полноширинный ряд отчёта, даже при скрытых таблицах; соседние графики остаются парными. Общий вариант `kpi-grid--five` располагает пять KPI в одну строку с минимальной шириной плашки `--analytics-kpi-min-width` (220px) и gap `--space-3`. При недостатке места прокручивается только ряд KPI через общий `ui-scrollbar`, доступный с клавиатуры; переключения на две или одну колонку нет. При печати плашки переносятся по доступной ширине листа, чтобы не обрезать значения. Корректировка карточки использует тот же дровер, что числовые ячейки отчёта.

- Первый текстовый сегмент общих хлебных крошек определяется активной группой `BNTNavigation`: «Предприятие» ведёт к цифровому двойнику, «Управление» — к отчётам. Ссылка домика всегда ведёт к `Предприятие / Цифровой двойник`, в том числе со страниц управления. `routeHref()` сохраняет маршруты приложения и их `.html`-варианты для статического preview; callbacks предпросмотра, модифицированные клики, escaping и ARIA не меняются.

### 14.9. Синхронизация

- `page-title-actions` и `grid-3` — непосредственные дети `page-content`, без внешнего `div-block` и обёртки старой студии. Шапка использует H4 и инфокнопку `sign_BTN_smallest`: прежнее описание показывается через общий инфопоповер. Компания, год, пара дат, валюта и единица используют тот же дровер «Фильтр», что «Данные» и «Отчёты», без локальной строки select. «Запустить синхронизацию» — Primary Small с контурной иконкой пункта меню `navigation.svg#nav-sync-outline` через `BNTUI.icon('sync')`. «Фильтр» — Secondary Small, последнее действие шапки.
- Содержимое синхронизации располагается в общем `grid-3` с `--space-3`: первая колонка содержит 1С и Pelogas друг под другом в `div-block`, вторая — сводку, третья — последние срезы. Внешние карточки используют оболочку `chart-card` с `--text-primary` и `--font-family-primary`. Сводка использует мастер `payment-summary-card`: число — `payment-summary-card__amount typography-indicator-base`, «источников и наборов» с новой строки — `payment-summary-card__amount--multiline` / Label Base, дополнительный текст — `payment-summary-card__description` / Body Smallest / Tertiary. Четыре плашки используют точный `dt3-metrics scenario-impact`, без вложенного `chart-card`: подпись Indicator Small / Tertiary, затем значение Label Small / Primary; две колонки и внутренний gap от мастер-компонента. Старые `sync-card` / `sync-metrics` и их фиксированные шрифты не используются. Расчеты, состав и расположение данных не меняются.
- Вариант `grid-3--reference-height` оставляет первую колонку по естественной высоте и задаёт соседним `--grid-reference-height`, без фиксированных px-ограничений и увеличения высоты источников из-за длинных срезов. Адаптер синхронизации измеряет пару карточек 1С/Pelogas вместе с gap, обновляет высоту при resize, изменении источников и загрузке шрифтов и отключает старый observer при перерисовке. Вторая и третья карточки растягиваются до этой высоты; переполнение прокручивается штатным `ui-scrollbar` в обеих темах. Общая адаптивность `grid-3` сохраняется.
- Источники используют позитивный `badge green`, надзаголовок «1С» / «Pelogas», заголовок Caption Smallest и описание Body Smallest в `card-with-image__body`, нижние бейджи — `badge default`. Общая композиция `chart-card > card-with-image__body` убирает только повторные padding, фон, радиус и автоматический верхний margin; шрифты, цвета и внутренние gaps остаются от мастер-компонента. Бейджи располагаются в `filter-summary__pills` и не растягиваются по ширине.
- Последние срезы используют общий `logistics-alert-list` с точной разметкой логистики, типографикой и отступами; маркеры — `logistics-alert--green`. Заголовок `sync-slices-title` — Caption Smallest, расположен вне прокрутки. Только список является `payment-risk-map__scroller ui-scrollbar` внутри `payment-risk-map__risk-column`, с общей маской фейда рисков и клавиатурным фокусом. Композиция `chart-card > payment-risk-map__risk-column` заполняет оставшуюся высоту, сохраняет внешние padding `--space-3`, включая 12px снизу, и не растягивается до мобильного минимума отдельной карты рисков. Основная подпись — Label Smallest / `--text-primary`, дополнительная — Body Smallest / `--text-tertiary`, внутренний gap 0. Цвет основной подписи закреплен в мастере, не наследуется из старой страницы. Правила списка живут в `components.css`, не дублируются в page styles. Порядок по timestamp, ограничение шести срезов 1С и расчёты сводки сохраняются.
- Запуск открывает общий правый дровер «Синхронизация источников» через `BNTUI.renderDrawer()`. Единственный прокручиваемый контейнер карточек — `quality-detail-drawer__fields ui-scrollbar`, с gap `--space-1` (4px), как в эталоне качества, без вложенного `filter-modal__fields` или `div-block`. Три проверки используют вариант `canvas-block--static`: та же поверхность и подписи `layout-item-label`, слева `layout-item-icon--positive` с check, без drag и последней кнопки. Подписи используют семейство `--font-family-primary`, основная — Label Smallest / Primary, дополнительная — Body Smallest / Tertiary; старые правила `.canvas-block small` не допускаются. Статический вариант имеет две колонки и рамку первой иконки 32px. Footer — «Применить срезы» / «Отмена»; Escape, закрытие и отмена не меняют данные, подтверждение не перезаписывает корректировки. Состояния ARIA, клавиатурный контур и возврат фокуса обслуживаются общей механикой дровера.
- `BNTUI.icon('sync')` оставляет исходный контурный рисунок меню 20×20 по центру SVG-рамки 24×24, без растягивания рисунка на всю рамку.

### 14.10. Статические строки со ссылками

Паспорт оборудования использует внешний `div-block` с gap `--space-3`. В шапке предиктива справа от скачивания расположен общий статичный фильтр истории ремонтов: `data-chart-filter`, вариант `static-date`, явное `data-chart-filter-title="История ремонтов"`. Он открывает существующий `chart-filter.js` без локальной копии дровера; явное название имеет приоритет над заголовком общего блока. Данные истории, рекомендации и экспорт не меняются.

- `BNTUI.renderCanvasAlertList(items, {label})` объединяет `logistics-alert-list` и строки `logistics-alert--canvas > canvas-block--static`. Gap списка и нижние отступы с разделителями берутся из `logistics-alert`, внутренний gap строки наследуется от него. Вложенный canvas не добавляет padding, фон, рамку, радиус, тень или blur; самостоятельный `canvas-block--static` не меняется.
- Иконка использует общую плашку `layout-item-icon--neutral`: фон `--system-elements-semantic-neutral-secondary-fade`, цвет `--system-elements-semantic-neutral-primary`. Пользовательский символ местоположения хранится в общем спрайте как `LocationMap`, заливка `currentColor`.
- Изображение бренда использует `layout-item-icon__image`: исходный логотип как маска, заливка `--text-primary`, чтобы он адаптировался к теме. Размер — `--space-5`, изображение полностью помещается в плашке без растягивания.
- Подписи сохраняют `layout-item-label`: Label Smallest и Body Smallest. Значение — `layout-item-label__link`; активный `href` передаёт адаптер страницы через `BNTShell.routeHref()`. Если переход ещё не реализован, у ссылки нет `href` или обработчика, задано `aria-disabled="true"`; нажатие ничего не открывает и не меняет URL.
- В паспорте оборудования список находится под парой круговых метрик. «Местоположение» использует адрес из модели и открывает текущий актив в 3D; «Бренд / TAKISH ENGINEERING» ведёт на `https://takish.kz/about_us`. Модель актива и прочие блоки паспорта не меняются.
- Продуктовая UI-палитра цифрового двойника: газ — Neutral Primary, дизтопливо — Mustard Primary, бензин — Turquoise Primary, нефть — Purple Primary. Легенда использует семантические токены, бейджи — соответствующие варианты общего `badge`. Подсветка warning/error использует Primary и Secondary Fade своего тона; mixed — Default: `--text-tertiary`, `--background-surface-4` и `--design-elements-border-default`. По решению пользователя от 09.10.2026 саму 3D-сцену, её физические материалы и палитру не менять и не пересаживать на UI-токены.

### Hue-палитры графиков

## 15. UX checklist для нового экрана

Перед завершением экрана проверить:

- [ ] Какая главная пользовательская цель на этом экране?
- [ ] Primary action понятен без чтения всей страницы?
- [ ] Часто используемые действия видимы сразу?
- [ ] Второстепенное не конкурирует с главным?
- [ ] Сложная задача разделена на понятные части?
- [ ] Есть понятная обратная связь о состоянии системы?
- [ ] Пользователь может безопасно отменить/изменить решение?
- [ ] Положение основных элементов стабильно и предсказуемо?
- [ ] Использованы токены, а не случайные HEX/px?
- [ ] Spacing соответствует шкале `8 / 12 / 24 / 48`?
- [ ] Cards используют `12/24px` padding и `24/48px` gaps?
- [ ] Учитывается состояние навигации?
- [ ] Адаптив следует inheritance-правилу?
- [ ] На `640–959` применена mobile typography scale?
- [ ] Borders и shadows не масштабируются?
- [ ] Light/Dark тема использует соответствующие semantic tokens?

## 16. Не додумывать

До отдельного подтверждения не вводить новые значения для:

- focus outline color token;
- error outline color token, если конкретный компонент не задает его семантически;
- неизвестных/неподтвержденных palette hex значений;
- дополнительных breakpoint-правил;
- произвольных spacing значений вне базовой шкалы;
- альтернативных typography weights или line-height.

Если макет требует нового значения — сначала проверить существующий токен/паттерн, затем согласовать новый.
