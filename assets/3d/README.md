# Dispatcher 3D integration

Source scene: https://batumi-terminal-3d.spry-tide-6642.chatgpt.site/
Imported 2026-09-10 at the project owner's request. The scene and its Three.js dependencies are self-hosted. No requests to the source site occur at runtime.

`terminal-scene.js` preserves the supplied model geometry and animation, and mounts it into a container using ResizeObserver. `hierarchy.js` builds the navigation tree. `dispatcher-3d.js` drives the shared side panel and keeps selection, camera focus, highlighting and URL in sync.

Zones and equipment placement are illustrative. Registered assets reuse `BNT_DATA.assets` without changing their metrics. Other tanks and equipment are explicitly marked as demonstration entities and do not link to fabricated passports. P-3 is mapped to model tank 3 for this demo. Zone membership and pump positioning require validation against a real plant register before operational use. Fill sliders only alter scene memory; they do not change the registry.

Three.js and OrbitControls are MIT licensed (see vendor/LICENSE). Vendor modules are the exact versions served with the source model; retain them as a matched set.

The active scene is `terminal-scene-realistic.js`. Its atmospheric background is configured in `terminal-atmosphere.js` using the official [Three.js r185 Sky](https://github.com/mrdoob/three.js/blob/r185/examples/jsm/objects/Sky.js), stored unmodified as `vendor/Sky.js` under the same MIT license. This is the WebGL counterpart of the [WebGPU sky example](https://threejs.org/examples/webgpu_sky.html), matching the self-hosted Three.js revision. Daylight follows the supplied reference settings (turbidity 5.6, Rayleigh 1.562, Mie 0.015/0.543, elevation 58.2, exposure 0.0535). Sky exposure is separate from model exposure. The shell Mood/theme control selects daylight or night through the existing `data-theme` observer. Night uses softer cool lighting and a procedural star layer underneath illuminated clouds. An 8% tint from the existing dark-sky palette gently blues the night atmosphere while preserving linear luminance; daylight is unaffected. No runtime CDN requests are made.

The terrain sits on a closed foundation extending 80 metres downward without moving roads or equipment. Sky and physical scene materials share a raymarched density field generated with the unmodified [r185 ImprovedNoise](https://github.com/mrdoob/three.js/blob/r185/examples/jsm/math/ImprovedNoise.js). Raymarching follows the official [WebGL volumetric cloud example](https://github.com/mrdoob/three.js/blob/r179/examples/webgl_volume_cloud.html), adapted for height clipping, existing scene colors, tone mapping and a deeper mist bed. Fog depth and cloud forms are 2.5 times the foundation thickness; the background layer stays below the terrain. A denser perimeter band dissolves the slab's sides, corners and upper contour, fading smoothly inside and outside the footprint and rising slightly above the edge with the same cloud density field. The center has no perimeter influence, and clear central rays bypass that volume. Material hooks preserve existing surface animation and handle instanced world positions; selection overlays remain unchanged. Night fog uses the same moonlit color as upper clouds instead of blending daylight color into the dark palette. The supplied cloud threshold/opacity/range are 0.29/0.16/0.17; sampling uses up to 113 steps on desktop and 64 on narrow viewports. Shared animation time respects pause, hidden pages and reduced motion; disposal releases the density texture.

The opening and port overviews preserve their camera distances and azimuths but use an elevation of 0.09 times the vertical field of view. This lowers the horizon by approximately 1.7 times the preceding adjustment from 0.325 to 0.24. Zone focus fits projected bounds rather than multiplying the zone width. Manual orbit stays at least 3 degrees above the horizon. Plan and top views remain top-down. Regression checks trace upper-frame rays at desktop and mobile aspect ratios to ensure that the sky is exposed, not merely allocated in the scene.

Entry: `/dispatcher`. Deep link example: `/dispatcher?object=pump101`.

Validation: JavaScript syntax checks; 22 HTTP route/dependency smoke checks; hierarchy integrity, unique paths, 55 tank nodes, registry values and P-3 to pump/valve links checked. Browser verification is recorded in the delivery report.

Run `node --test tests/dispatcher-3d.test.mjs tests/terminal-atmosphere.test.mjs` with Node 24+. These construct actual Three.js geometry using an injected non-GPU renderer and validate camera math, scene visibility, tank fill, raycasting, navigation IDs, atmosphere settings, the shared fog contract and cleanup. They are not pixel or GPU shader tests.

WebGL availability does not block the hierarchy or asset drawer. Only camera controls are disabled when a graphics context cannot be created.
